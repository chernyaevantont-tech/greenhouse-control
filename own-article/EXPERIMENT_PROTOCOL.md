# Протокол экспериментов

**Тема.** Data-efficient интерпретируемое предиктивное управление микроклиматом
теплицы на основе разреженной идентификации динамики (SINDy) с корректной
идентификацией для долгосрочного прогноза и безопасной онлайн-адаптацией.

**Симулятор.** `gl_gym/GreenLightTomato-v0` (GreenLight-Gym2). Все утверждения —
**in-silico** (в симуляции), не переносятся на реальную теплицу без отдельной
валидации.

## Глоссарий (англоязычные термины и общепринятые русские эквиваленты)

| Термин (англ.) | Русский академический термин | Пояснение |
|---|---|---|
| MPC (Model Predictive Control) | управление с прогнозирующими моделями (модельно-прогнозирующее управление) | на каждом шаге решается задача оптимизации на конечном горизонте по модели объекта |
| RL (Reinforcement Learning) | обучение с подкреплением | оптимальная политика выучивается из взаимодействия со средой по сигналу вознаграждения |
| SINDy (Sparse Identification of Nonlinear Dynamics) | разреженная идентификация нелинейной динамики | восстановление уравнений движения как разреженной комбинации базисных функций |
| SINDy-LOM (Library Optimization Mechanism) | SINDy с оптимизацией библиотеки базисов | автоматический подбор базисных функций с прицелом на долгосрочный прогноз |
| surrogate model | суррогатная (заменяющая) модель | вычислительно дешёвая модель-заменитель дорогой имитационной модели |

| oracle | эталонный регулятор по истинной модели | верхняя достижимая граница в данной постановке |
| black-box / grey-box / glass-box | «чёрный» / «серый» / «прозрачный» ящик | непрозрачная / полуэмпирическая / полностью интерпретируемая модель |

| sparsity | разреженность | доля нулевых коэффициентов модели |
| condition number (κ) | число обусловленности | мера чувствительности регрессии к возмущениям данных |
| STLSQ (sequentially thresholded least squares) | последовательный пороговый метод наименьших квадратов | базовый разреженный оптимизатор SINDy |
| SR3 (sparse relaxed regularized regression) | разреженная релаксированно-регуляризованная регрессия | оптимизатор с расщеплением переменных |

## 1. Цель и гипотеза

### 1.1 Область применимости и единый протокол
Все сравнения — в рамках **сравниваемого набора регуляторов** при едином протоколе:
одинаковые сценарии погоды, горизонты и ограничения; **равный бюджет настройки
гиперпараметров** (одинаковое число попыток, один метод поиска); единые правила
сбора данных и **единая валюта затрат данных** — число обращений к симулятору и
число наблюдаемых теплице-суток. Эффективность по данным — это **кривая**
(показатель vs бюджет), а не фиксированное отношение.

### 1.2 Эталоны и классы регуляторов
| Класс | Экземпляры | Роль |
|---|---|---|
| Model-based, точная модель | **oracle-MPC** (MPC по истинной модели симулятора) | верхний эталон (оптимум *относительно симулятора*, с анализом чувствительности к горизонту/решателю/фиделити) |
| Grey-box (редуцированная физика) | MPC по упрощённой первопринципной модели | физический интерпретируемый компаратор |
| Data-driven, black-box | **PPO**, **SAC**, экономичный по данным RL (offline/model-based), **NN-MPC** | основные конкуренты |
| Эвристика | rule-based (правила агронома) | нижний эталон |
| **Предлагаемый метод** | **SINDy-MPC** (интерпретируемый разреженный суррогат) | предмет работы |

### 1.3 Пространство критериев (фронт Парето)
Фронт ищется в **4 измеримых осях**: (1) EPI; (2) бюджет данных; (3) число/площадь
нарушений ограничений; (4) адаптивность (восстановление EPI при сдвиге погоды).

**Интерпретируемость — не ось, а квалифицирующий шлюз** (gate): регулятор «прозрачен»,
если он glass-box (явные уравнения) + проходит проверки физической/размерной
согласованности выше порога + структурно устойчив при бутстрэпе. Отдельно
измеряется **цена прозрачности** (price of interpretability) — зазор между фронтом
Парето прошедшего шлюз подмножества и безусловным фронтом.

### 1.4 Центральная гипотеза
В условиях §1.1 предлагаемый метод занимает компромиссно-недоминируемую позицию в
4-мерном пространстве §1.3: сокращает разрыв до oracle-MPC не хуже, чем сильнейший
из black-box data-driven регуляторов и чем grey-box, при равном или меньшем бюджете
данных, проходя при этом шлюз прозрачности и автоматически настраиваясь под объект
из данных. Иными словами — **цена прозрачности мала**. Истинна только при выполнении
Г2–Г4.

### 1.4.1 Что такое «предлагаемый метод» и предрегистрация рецепта
**Предлагаемый метод** — замкнутый контур управления с прогнозирующей моделью (MPC),
внутренней моделью прогноза которого служит **интерпретируемый разреженный суррогат
динамики теплицы**, восстановленный из данных (SINDy-MPC). Конвейер из четырёх стадий:
1. **Сбор данных** — эвристический регулятор + сигнал возбуждения (PRBS/шум) на погоде
   региона.
2. **Идентификация суррогата** — разреженная регрессия, дающая **явные дискретные
   уравнения** `x_{k+1} = f(x_k, u_k, d_k)` с малым числом ненулевых членов,
   проходящие шлюз прозрачности; степень 1 — для аналитической встраиваемости в MPC.
3. **MPC** — суррогат встраивается в решатель (CasADi/do-mpc,
   [build_mpc_controller](article_experiment_utils.py:700)) и оптимизирует EPI при
   ограничениях по температуре, CO₂ и относительной влажности на горизонте.
4. **Онлайн-адаптация (для Г4)** — итеративная агрегация данных (DAgger) либо
   расширенный фильтр Калмана (EKF-SINDy) + монитор выхода за обучающее распределение
   (OOD) + безопасный откат.

**Два уровня определения.** Гипотеза §1.4 утверждается про *архитектуру/семейство*
(«разреженный суррогат внутри MPC»), которая зафиксирована. *Конкретный рецепт
идентификации* — какое сглаживание (конечные разности / калмановское), какой
оптимизатор (STLSQ / ансамблевый / с ограничениями устойчивости), какая библиотека
(физическая / SINDy-LOM) — **не задаётся заранее, а выбирается в эксперименте E2**.

**Предрегистрация (против цикличности вывода).** Рецепт замораживается по метрикам
*идентификации/валидации* (устойчивость многошагового прогноза, встраиваемость в MPC,
прозрачность) — **до** и **независимо** от замкнутого EPI на отложенных тестовых
сезонах. Тем самым выбор рецепта в E2 не контаминирует честное сравнение в E3 (Г1).
Текущая реализация-прототип: [fit_sindy](article_experiment_utils.py:428) (STLSQ +
физические признаки, степень 1) + [build_mpc_controller](article_experiment_utils.py:700);
E2 обобщает её до робастного рецепта.

### 1.5 Проверяемые под-гипотезы
- **Г1 (конкурентоспособность при ограниченных данных).** Разрыв до oracle-MPC не
  больше, чем у сильнейшего black-box и у grey-box, при равном/меньшем бюджете данных;
  цена прозрачности ниже порога. *Опровержение:* какой-либо регулятор даёт значимо
  меньший разрыв при сопоставимом/меньшем бюджете.
- **Г2 (устойчивость долгосрочного прогноза — диагностическая).** Существует рецепт
  идентификации из {Kalman smoothing; SINDy-LOM; ограничения устойчивости},
  **минимальный состав которого определяется абляцией**, устраняющий расхождение
  многошагового разомкнутого прогноза (доля расходящихся траекторий → ~0). Качество
  разомкнутого прогноза необходимо, но недостаточно — арбитр — замкнутый контур (Г1);
  модель допускается к сравнению только при встраиваемости в MPC при приемлемой
  стоимости. *Опровержение:* ни один состав не устраняет расхождение, либо устойчивая
  open-loop модель не встраивается / не улучшает замкнутый EPI.
- **Г3 (прозрачность без потери качества).** Модель glass-box, проходит проверки
  физической/размерной согласованности, структурно устойчива, и не уступает в
  замкнутом контуре ни NN-MPC, ни grey-box. *Опровержение:* проверки не проходят,
  структура неустойчива, либо хуже в управлении хотя бы одного из этих двух.
- **Г4 (безопасная адаптация под сдвигом).** (а) Онлайн-адаптация (DAgger или
  EKF-SINDy) восстанавливает EPI при погоде вне обучающего распределения; (б) сигнал
  OOD (Mahalanobis и/или дисперсия ансамбля) предсказывает рост ошибки и нарушений →
  guard снижает нарушения; (в) оптимизатор не эксплуатирует ошибки суррогата
  (траектория преимущественно in-distribution). *Опровержение:* OOD не коррелирует с
  ошибкой, guard не помогает, либо оптимизатор систематически уходит в области
  переоценки.

### 1.6 Нулевые гипотезы (статистика)
Для каждого парного сравнения H₀: распределения целевой метрики (EPI, нарушения,
ошибка) неразличимы. Отвергается по критерию знаковых рангов Уилкоксона при p<0.05 с
поправкой на множественные сравнения, с указанием размера эффекта и доверительных
интервалов (бутстрэп), по выборке ≥10 независимых прогонов.

## 2. Данные и сценарии

- **Локация:** Ростов-на-Дону (47.24 N, 39.71 E). Реальная погода — ERA5/ERA5-Land
  через Open-Meteo; формат и вывод производных (температура неба, почвы) — см.
  [weather_data_methodology.md](weather_data_methodology.md), реализация почвы —
  [rostov_soil.py](rostov_soil.py).
- **Годы:** 2018–2023. CSV в `gl_gym/data/weather/Rostov-on-Don/`.
- **Сплиты:**
  - *Train / in-distribution:* подмножество лет (например 2018–2020) и стартовых дат.
  - *Out-of-distribution (OOD):* остальные годы (2021–2023) и сезоны, отличные по
    погоде; используются в Г4/E5. Дополнительно — экстремальные эпизоды (волны жары/
    холода) как явный OOD.
- **Возбуждение для идентификации:** rule-based + шум (есть) + PRBS/мультисинус
  (псевдослучайные/многочастотные сигналы на актуаторы) для идентифицируемости;
  контроль числа обусловленности κ.
- **Бюджеты данных:** 1/3/7/14/30/60 сут → кривая data-efficiency.
- Перед созданием env вызывать `rostov_soil.apply_rostov_soil()` (погода кэшируется).

## 4. Эксперименты

> Шаблон: **Цель · Гипотезы · Факторы · Процедура · Критерий · Артефакты.**

### E0. Каноническая постановка и метрики (фундамент)
- **Цель:** перейти от ошибки setpoint к EPI; зафиксировать ограничения, реальные
  единицы действий, единую валюту данных и равный бюджет гиперпараметров.
- **Процедура:** реализовать EPI и penalty (штраф ограничений) в
  [rollout_metrics()](article_experiment_utils.py:883); задать ymin/ymax по T/CO₂/RH.
- **Артефакты:** модуль метрик; конфиг протокола (сценарии, горизонты, бюджеты, HP).

### E1. Данные и сценарии (фундамент)
- **Цель:** train/in-dist/OOD-сплиты по 2018–2023; сигналы возбуждения; кривая бюджета.
- **Процедура:** генерация датасетов rule-based+шум(+PRBS) на бюджетах данных;
  фиксация сплитов.
- **Артефакты:** `.npz` датасеты; таблица сплитов; κ по бюджетам.

### E2. Лестница идентификации суррогата (ядро)
- **Цель:** найти рецепт идентификации, устойчивый в долгом прогнозе и пригодный для MPC.
- **Гипотезы:** Г2; частично Г3.
- **Факторы (факторная абляция):**
  - денойзинг/производная: finite difference · Savitzky–Golay · **Kalman smoothing**
    ([kalman_smoothing_sindy_stevenshaas_2024](../articles/kalman_smoothing_sindy_stevenshaas_2024_arxiv_2405.03154.pdf));
  - оптимизатор: STLSQ · SR3 · **Ensemble-SINDy**
    ([ensemble_sindy_fasel_2022](../articles/ensemble_sindy_fasel_2022_arxiv_2111.10992.pdf)) ·
    **constrained/stability** ([constrained_sparse_galerkin_loiseau_2018](../articles/constrained_sparse_galerkin_loiseau_2018_arxiv_1611.03271.pdf),
    [trapping_sindy](../articles/trapping_sindy_kaptanoglu_2021_arxiv_2105.01843.pdf));
  - библиотека: raw · physics (ручная) · **SINDy-LOM** (автооптимизация под долгий
    прогноз, [sindy_lom_library_optimization_yonezawa_2025](../articles/sindy_lom_library_optimization_yonezawa_2025_arxiv_2507.18220.pdf));
  - степень: 1 (для MPC) · 2 (верхняя планка open-loop).
- **Шлюзы:** (1) **MPC-embeddability** — модель допускается к E3, только если
  встраивается в CasADi/do-mpc при приемлемой стоимости решателя; (2) **прозрачность**
  (см. §1.3).
- **Критерий:** Pareto по {rollout-стабильность, шумоустойчивость, MPC-стоимость,
  closed-loop EPI}; результат — рекомендованный минимальный рецепт.
- **Артефакты:** таблица абляции; рисунок «rollout-RMSE и доля расходящихся vs бюджет»;
  таблица проверок знаков/размерностей.

### E3. Замкнутый MPC-бенчмарк (ядро)
- **Цель:** сравнить регуляторы по EPI и ограничениям.
- **Гипотезы:** Г1, Г3.
- **Регуляторы:** rule-based · PPO · SAC · NN-MPC · **SINDy-MPC** (рецепт из E2) ·
  grey-box-MPC · oracle-MPC.
- **Процедура:** замкнутые прогоны на тест-сезонах; равный бюджет HP; ≥10 прогонов.
- **Критерий:** разрыв до oracle-MPC; Парето-позиция; цена прозрачности.
- **Артефакты:** главная таблица mean±CI; Парето-диаграммы (EPI vs данные/нарушения).

### E4. Онлайн-адаптация
- **Цель:** восстановление EPI под сдвигом погоды.
- **Гипотезы:** Г4(а).
- **Факторы:** offline · **DAgger** ([run_dagger](article_experiment_utils.py:927)) ·
  **EKF-SINDy** ([ekf_sindy_rosafalco_2024](../articles/ekf_sindy_rosafalco_2024_arxiv_2404.07536.pdf),
  [online_sindy_kalman_bifurcating_rosafalco_2024](../articles/online_sindy_kalman_bifurcating_rosafalco_2024_arxiv_2411.04842.pdf)).
- **Критерий:** восстановленный EPI, число нарушений, стоимость адаптации.
- **Артефакты:** кривые адаптации по итерациям/времени.

### E5. Генерализация + OOD
- **Цель:** связать новизну входа с риском и проверить guard.
- **Гипотезы:** Г4(б,в).
- **Процедура:** матрица «обучен на сезоне A → тест на B» по годам/датам; два сигнала
  доверия — **Mahalanobis distance** и **дисперсия ансамбля**; корреляция сигналов с
  rollout-RMSE и нарушениями; ablation guard (с/без OOD-отката); проверка, что
  замкнутая траектория остаётся in-distribution.
- **Критерий:** значимая корреляция OOD↔ошибка; снижение нарушений с guard.
- **Артефакты:** матрица генерализации; scatter OOD↔ошибка; ROC детектора.

### E6. Анализ чувствительности
- **Цель:** робастность выводов.
- **Факторы:** цены энергии/CO₂; горизонт MPC; веса стоимости; порог STLSQ;
  **параметрическая неопределённость кропа 0–30%**; чувствительность oracle к
  горизонту/решателю/фиделити модели.
- **Артефакты:** tornado/линейные графики чувствительности EPI.

### E7. Инъекция отказов и безопасность
- **Цель:** безопасность при отказах датчиков/актуаторов.
- **Гипотезы:** safety-часть Г4.
- **Процедура:** [FaultInjector](../greenhouse_mvp/environment/fault_injector.py)
  (stuck/offset/dead) на датчики/актуаторы; сравнение деградации EPI и нарушений
  с/без OOD-супервизора.
- **Артефакты:** таблица деградации по типам отказов.

### E8. Статистическая достоверность (валидность всех Г)
- **Цель:** валидный вывод.
- **Процедура:** **настоящий источник дисперсии** — варьировать seed в *сборе train*
  (переобучать модель на каждом seed); ≥10 прогонов; bootstrap CI; размер эффекта;
  Wilcoxon с поправкой на множественные сравнения. (Текущий
  [07_multi_seed_benchmark.ipynb](07_multi_seed_benchmark.ipynb) невалиден: модели по
  seed идентичны.)
- **Артефакты:** таблица значимости; boxplot’ы по seed.
