
## EPI берётся из экономики симулятора gl_gym, не изобретается
Для статейных экспериментов E0–E3 первичная метрика EPI [EUR/m2·сезон] = сумма per-step `profit` из gl_gym GreenhouseReward, считываемого через `env.step(...)` info (greenlight_env.py:279 возвращает info={**reward_info,"controls":u}). В info есть profit, gains/revenue, variable_costs, heat_cost, co2_cost, elec_cost, fruit_growth_dm, *_penalty. Декомпозиция затрат и энергии (kWh/m2, kg/m2) выводится оттуда же по ценам env (fruit 1.6 €/kg, heat 0.09 €/kWh, elec 0.3 €/kWh, co2 0.3 €/kg, dmfm 0.065). Коридоры ограничений берутся с живого env: constraints_low/high порядок [CO2,T,RH] = CO2∈[300,1600] ppm, T∈[15,34]°C, RH∈[50,85]%. Реализация: protocol_config.read_env_economics(); article_experiment_utils ECON_FIELDS/_econ_row/epi_metrics; econ захватывается в collect_rule_based_dataset и всех rollout_*. Обоснование: переиспользовать экономику симулятора (van Laatum GreenLightGym), не выдумывать цены — воспроизводимо и согласовано. Состояние модели x: x[2]=tAir(°C прямо), x[0]=co2 density (→ppm через co2dens2ppm), x[15]=vapor pressure (→RH через vaporPres2rh, satVp=610.78*exp(17.2694*T/(T+238.3))), x[25]=fruit DM (cFrt).

## oracle-MPC = CEM по истинной модели env.F; grey-box = SINDy physics_no_cross
E3 регуляторы. oracle-MPC реализован как receding-horizon CEM (cross-entropy shooting) поверх истинного CasADi-интегратора симулятора env.unwrapped.F (nx=28,nu=6,p=218=10 weather+208 params; action→full control input = identity при normalize_actions=False). Тот же climate-tracking objective, что у SINDy-MPC → разрыв изолирует фиделити модели = EPI-верхний эталон относительно симулятора. ВАЖНО: встраивание F в do-mpc как discrete model (set_rhs=F(...)['xf']) технически работает символически, НО Ipopt с чувствительностями через жёсткий интегратор недопустимо медленный (первый make_step не завершился за минуты) — отвергнуто. CEM использует F.map(K) для батча; ~1.2 c/шаг (forward F ≈1.14 мс) → для article запускать на сокращённом числе сидов. grey-box-MPC реализован переиспользованием: fit_sindy(feature_variant="physics_no_cross", threshold≈1e-6) даёт плотную редуцированную линейную физ-модель, встраиваемую существующим build_mpc_controller (никакого нового MPC-кода). PPO/SAC — stable_baselines3 с MultiInputPolicy (obs — Dict space). Реализация: article_experiment_utils.rollout_oracle_mpc, train_rl/rollout_rl, paired_stats (Wilcoxon+Holm+bootstrap CI). Дисперсия — пересбор train по сидам (а не только seed прогона) — чинит претензию протокола к 07_multi_seed.
